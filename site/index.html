blip

A small Lisp dialect implemented in V, built around an explicit CEK machine with real tail calls and an embeddable core.

  • reader
  • tail calls
  • closures
  • loop / dotimes
  • letrec
  • modules (provide/require, machine only)
  • errors as values
  • file I/O
  • let*
  • rest params
Early, and honest about it. The reader and the machine run real programs, and every test on this page is executed by CI. The remaining pieces are listed rather than hidden — see the roadmap. This page is hand-written for now; the plan is to generate it from blip itself.

A taste

(define (fib n)
  (if (< n 2)
      n
      (+ (fib (- n 1))
         (fib (- n 2)))))

(fib 20)          ;=> 6765

Only #f is false, as in R5RS and Clojure: 0, "", nil and () are all true. Ruby and JavaScript say the opposite, which is why everyone arriving from them has to relearn this.

Tail calls are real, not bounded

The machine keeps an explicit continuation stack on the heap and reuses the frame in tail position instead of pushing. A loop does not grow the stack; it grows nothing at all.

TestIterationsResultStack
self tail call250,0002500000
mutual tail call20,000pong0
tail call in cond100,0001000000
tail call in let50,000500000
loop, 20,000 rounds20,0001999900000

A stack depth of 0 at the end is the point. If the loop were recursive rather than iterative, that column would be 250,000.

Embedding

The machine is a library, not a program. It holds no global state, it takes the arena it reads into, and print output is collected into a field instead of written to a terminal:

import vlib.blip.reader
import vlib.blip.machine

res := reader.read_all('(+ 1 2)')
mut m := machine.new_machine(&res.arena)
value := m.run(res.forms)!
println(value)   // 3

The plan is a Host interface so that printing, reading and loading come from the embedder rather than from the operating system, which is also what makes a REPL testable without a terminal.

Try it

git clone https://github.com/metif12/blip
cd blip
v -cc gcc -o blip.exe blip.v
.\blip.exe examples\01_basics.lip

Use -cc gcc: the default C backend in the pinned V release fails to compile this checkout, and CI enforces the same flag so the two agree.

Where it goes next

  • Macros in the JavaScript backend. blip emit-js already runs six of the seven examples byte-for-byte under node; only 05_pipelines.lip is refused, for defmacro and quasiquote.
  • A real commit-message linter as an installable tool: the program exists (programs/lint_commit.lip), what remains is the CLI wiring.
  • This website, generated by blip and served through V's veb.
